## 0. 北极星与边界

**最终目标**：在 DSH 里一句「帮我打 Forest Follies」，插件就能从大地图进关、战斗、
死亡后自动重试，最终**稳定通关**；同时引擎里**不出现任何游戏专用代码**，并用 1–2 款
副本游戏证明这一点。

**主线顺序**：可测 → 不卡死 → 看得懂 → 会躲会打 → 会学 → 泛化。
没有度量就是盲调，所以「可测」排在第一位。

**明确不做**（投入产出比差，且对通关不是必需）：

- 视觉 SLAM / 地图拼接 / 回环检测；
- 行为克隆、强化学习；
- 公开分享游戏精灵模板（版权问题）。

## 1. 与 v1 的主要差异

| v1 | v2 | 理由 |
|:--|:--|:--|
| 回放/评测放在 §11 末尾 | **阶段 A 第一优先** | v1 的指标都需要真值，没有评测就无法判断改动是否变好 |
| 场景状态机是 P0 第 2 项 | **阶段 B，排在感知之前** | 不能自动重试就跑不了多局评测；现策略在死亡/菜单界面仍按住 RIGHT+X |
| L2 状态源放 P2 | **本地真值源提前到阶段 A，只用于标注和评测** | 给视觉感知提供 ground truth，运行时不依赖 |
| 模板库为主要检测路线 | **启发式 vs 轻量检测器用数据二选一** | 手绘逐帧动画下模板维护成本高 |
| 模型 0.5–2 Hz 做战术 | **模型只做战略 / 复盘 / 调参（事件驱动）** | 工具调用 3–5 s，最多 0.2–0.3 Hz |
| 技能直接基于预测 | **先做动作标定 + 技能仲裁** | 没有自身动力学参数，「预测闪避」仍是反射 |
| WorldState schema 2（破坏性） | **schema 1 加法演进** | STATE.md 承诺只做加法；插件渲染与契约测试不受影响 |
| 泛化在 P2 才开始 | **副本游戏从阶段 B 起做冒烟** | 防止把 Cuphead 特化写进引擎 |
| 验收用「持续下降」 | **关卡 / 局数 / 成功率 / 相对基线** | 可判定 |

## 2. 现状要点（与本方案直接相关的代码事实）

- `PolicyRunner`（`engine/dsh_game_core/policy.py`）：hold + advance + 威胁半径闪避 +
  交战停步 + 固定间隔跳跃/冲刺 + 镜头滚动卡住检测；**不区分场景**。
- `session.policy_start` 创建 `PolicyRunner` 时**没传 `scene_source`**，`status.scene` 恒为 `None`。
- `SafetyGate.evaluate()` 每拍只查反作弊与 F12；**策略环不逐拍校验前台窗口**
  （`game_plan` 是逐拍校验的）。
- `state._detect_threats` 是帧差 + 网格聚类，只排除 `self_pos` 附近一个圆；**持续射击产生的
  己方子弹会被当成 threat**，触发交战停步/闪避。
- `grab_raw` 是整屏抓取后裁剪窗口区域。
- `game_policy` 只有 `start / stop / status`，**没有目标参数**，也没有事件流。
- 性能：58 Hz（无追踪）/ 52.7 Hz（追踪，每 3 拍一次）/ 关卡内实测约 35 Hz。

## 3. 目标架构：三个环，按速度分工

```
  模型环（DSH，事件驱动，约每局几次调用）
    目标 / 姿态 / 风险 → game_policy           ← 事件摘要 / game_review 复盘包
  ─────────────────────────────────────────────────────────────────
  慢环（本地，3–5 Hz，后台线程；必要时子进程）
    OCR → 场景追踪器（滞回）→ 场景门控 / 恢复脚本 / 战术姿态
  ─────────────────────────────────────────────────────────────────
  快环（本地，≥50 Hz）
    抓帧 → 玩家追踪 + 实体跟踪 → 技能仲裁 → 按键
    每拍：安全闸（反作弊 / F12）+ 前台校验
  ─────────────────────────────────────────────────────────────────
  旁路：录制环形缓冲（缩略图 + 输入 + WorldState + 事件）
```

约束：

1. 快环**只读**慢环的缓存结果（带时间戳和版本号），永不等待慢环；
2. 模型**不进**战术层，只做战略、复盘与调参；
3. 每一层判断不了的情况上报给更慢的一层，**快环不猜**；
4. 安全闸与状态来源无关，任何新能力（自动重试、菜单导航）都不得绕过它。

## 4. 阶段 A：可测（第 1 优先，约 1 个迭代）

| 交付物 | 落点 | 说明 |
|:--|:--|:--|
| 录制器 | `engine/dsh_game_core/recorder.py` | 内存环形缓冲：15 s，10–15 Hz 缩略图 + 输入 + WorldState + 事件；死亡 / 停止 / 手动触发时落盘为 episode（目录：帧 PNG/JPG + `events.jsonl`） |
| 离线回放 | `python -m dsh_game_core replay <episode>` | 感知与策略对录像确定性重跑（注入假时钟与假控制器），输出逐帧对比 |
| 自动评测 | 引擎子命令或本地 harness `eval.py` | 跑 N 局，统计受击/分钟、死亡/局、卡住秒数、推进距离、Hz p50/p90 |
| 端到端延迟 | 同上 | 「按下跳跃 → 画面中玩家开始位移」的毫秒数，用于设定闪避窗口 |
| 本地真值源 | **仅本机，不进仓库** | Cuphead 单机无反作弊：本地 mod 输出玩家坐标、HP、敌人/弹幕列表。**只用于自动标注与评测，运行时不依赖**；公开仓库只放 provider 接口 |
| 基线报告 | 本地 | 当前版本的全部指标；后续目标一律写成「相对基线」 |

**退出条件**：一条命令跑完 10 局并输出指标表；视觉玩家坐标与真值的误差可自动计算。

## 5. 阶段 B：不卡死（约 1 个迭代）

1. **慢通道**：OCR 移出请求路径，后台线程 3–5 Hz 写缓存；限制 onnxruntime intra-op 线程数；
   若快环 p90 明显下降则改子进程。
2. **场景追踪器**：融合 OCR 关键词、近黑屏、HUD 是否存在等信号，加滞回（连续 N 次一致才切换）。
3. **profile 新增 `scenes` 段**，按场景声明：
   - 识别规则；
   - 允许的按键（例：`death` 只允许 confirm 与方向键，禁止 dash/SHIFT）；
   - 恢复脚本：每一步带「期望到达的下一场景」与超时，超时即停，不盲目重试。
4. **场景门控**：只有 `gameplay` 运行战斗策略；其他场景只执行恢复脚本；`unknown` →
   松开所有按键并发出事件。
5. **修补现有缺口**：`policy_start` 接上 `scene_source`；`PolicyRunner` 逐拍前台校验（失焦即松手暂停）。
6. **事件流**：`game_policy status` 返回自某 cursor 以来的事件（死亡、重试、卡住、未知界面、过关）。
7. **菜单安全**：恢复脚本只走白名单路径；未知菜单**绝不按 confirm**。

示意（profile 片段）：

```json
"scenes": {
  "death":  {"keywords": ["RETRY", "EXIT TO MAP"], "allow": ["confirm", "up", "down"],
             "recover": [{"press": "confirm", "expect": "loading", "timeout_ms": 3000}]},
  "equip":  {"keywords": ["EQUIP"], "allow": ["back"],
             "recover": [{"press": "back", "expect": "gameplay", "timeout_ms": 1500}]},
  "gameplay": {"mode": "level"}
}
```

**退出条件**：连续 20 次死亡全部自动重试、零人工干预；副本游戏能识别其菜单，或正确判为
`unknown` 并停下。

## 6. 阶段 C：看得懂（约 2 个迭代）

新增 `engine/dsh_game_core/tracking.py`，把「运动簇」升级为「轨迹」：

1. **检测**：现有帧差簇 + 颜色作为通用地板；
2. **关联**：最近邻 + 线性预测，稳定 ID，记录 age / 速度（先不上 Kalman，不够再加）；
3. **分类启发式**：
   - 己方子弹：出生在玩家附近、速度方向与 facing 一致 → 剔除；
   - 弹幕：小、快、朝玩家；
   - 敌人：大、慢或长寿命轨迹；
4. **威胁量**：`time_to_hit`、相对方位（前 / 后 / 上 / 下）；
5. **技术路线由数据决定**：用阶段 A 的真值自动生成标注，在同一回放集上比较
   「启发式 + 模板」与「onnx 轻量检测器（320px 输入）」的召回 / 精度 / 耗时，达标者胜出；
6. **WorldState 加法演进**：`scene` 字符串不变；新增 `scene_info`、`tracks[]`、
   `player.vx/vy/facing/grounded`，均带 `confidence` / 时间戳；
7. **性能预算**：抓帧 ≤2 ms、玩家追踪 ≤2 ms、实体跟踪 ≤4 ms、决策 ≤1 ms，合计 ≤10 ms；
   整屏抓取改为 region 抓取。

**退出条件**：回放集上弹幕 / 敌人召回 ≥70%、精度 ≥80%；快环 p90 ≥50 Hz；
实机中己方子弹不再触发闪避或交战停步。

## 7. 阶段 D：会躲会打（约 2 个迭代）

1. **动作标定**：安全场景自动执行跳跃 / 冲刺，用玩家追踪测出跳高、滞空、冲刺距离，写入
   `profile.skills`；
2. **技能库**：`face` / `shoot_at` / `evade` / `jump_over` / `retreat` / `hold` / `parry`，
   每个技能声明前置条件、承诺时长、可否打断、冷却；
3. **仲裁器**：Recover > Evade > Engage > Advance > Explore；承诺期内不被低优先级打断；
4. **战术姿态**（慢环）：推进 / 清场 / 后撤 / 保守（低血量），调整仲裁器参数；
5. **替换固定间隔盲跳**：只有当「按障碍 / 坑触发的跳跃」在评测中不劣于盲跳时才删除。

**退出条件**：Forest Follies 10 局，受击/分钟较基线 −50%，到达中段成功率 ≥60%。

## 8. 阶段 E：会学（约 1–2 个迭代）

1. **`game_policy` 目标参数**：`mode`（level / overworld）、`posture`、`risk`、`target_route`；
2. **`game_review` 工具**：死亡后返回死前 3–6 张关键帧 + 事件时间线 + 当前参数，模型分析
   死因并提出 profile 补丁；
3. **补丁闭环**：候选 profile → 自动评测 N 局 → 优于原版才 `game_memory save`，否则丢弃；
   每次改动保留 diff 与指标，可回滚；
4. **大地图**：模型看截图定方向；本地提供「朝方向走，直到出现交互提示」原语
   （提示出现处即入口），不做视觉建图；
5. **knowledge 笔记**：模型把 Boss 阶段、危险点写进 profile `knowledge`，开局时读取。

**退出条件**：从大地图出发零干预完成 Forest Follies ≥7/10；模型复盘至少产出一次经评测
证实有效的参数改进；模型调用 ≤10 次/分钟。

## 9. 阶段 F：泛化（贯穿全程，最后收口）

- 副本游戏（不同画风的 2D 横版、无反作弊）从阶段 B 起做冒烟：可观察 / 可过菜单 / 可基础移动；
- 每加一款游戏记录人工配置量（profile 条目数、标定耗时），作为泛化指标；
- 代码 review 规则：引擎中出现游戏名或特化分支直接打回。

## 10. 验收总表

具体数字在阶段 A 基线出来后校准。

| 阶段 | 协议 | 指标 |
|:--|:--|:--|
| A | 当前版本 10 局 | 产出基线报告；真值误差可自动计算 |
| B | 20 次死亡 | 自动恢复率 100%，卡死 0 次 |
| C | 回放集 + 实机 | 召回 ≥70%、精度 ≥80%、p90 ≥50 Hz、端到端延迟有实测值 |
| D | Forest Follies 10 局 | 受击/分钟 −50%（相对基线），到中段 ≥60% |
| E | 从大地图开始 10 局 | 通关 ≥7/10；模型调用 ≤10 次/分钟 |
| F | 副本游戏 | 可观察 / 过菜单 / 基础移动；记录人工配置量 |

## 11. 风险与对策

| 风险 | 对策 |
|:--|:--|
| 纯视觉检测召回不足 | 阶段 C 用数据比较启发式与轻量检测器，保留切换余地 |
| OCR 拖慢快环 | 限线程，不行改子进程；p90 列为验收项 |
| 自主重试误操作（误按菜单、窗口失焦） | 场景白名单、逐拍前台校验、`unknown` 停下上报 |
| 过拟合 Cuphead | 副本游戏冒烟 + review 规则 |
| 真值 mod 合规风险 | 仅本地使用，仓库只有接口 |
| 模型复盘改坏参数 | 补丁必须经评测胜出才保存，可回滚 |

## 12. 公开仓库与合规

- 不提交：游戏精灵模板、真值适配器 / mod、offset、游玩录像、本机路径；
- 反作弊游戏：只读也不接，直接拒绝；
- 公开仓库只放：WorldState 字段定义、provider 接口、`scenes` / `skills` schema、安全说明；
- README / 市场口径：视觉保底 + 可选本地 provider，不承诺「大部分游戏能读接口」。

## 13. 开工顺序：前三个 PR

1. **修补现有缺口**：`policy_start` 接上 `scene_source`；`PolicyRunner` 逐拍前台校验；
   非 gameplay 场景松开所有按键（附单测）；
