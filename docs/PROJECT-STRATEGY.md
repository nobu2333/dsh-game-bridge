# dsh-game-bridge 总体方案：看、玩、学

> 本地文档，不入库。日期：2026-10-30
> 状态：当前实现的共识版本；与 `OPTIMIZATION-PLAN.md` / `OPTIMIZATION-PLAN.v2.md` 相比，本文是面向「整体产品」的定稿说明。
> 公开仓库只保留 schema / 接口 / 安全说明；本文、游戏模板、录像、危险卡、真值适配器都留在本地。

---

## 1. 一句话定义

把「玩家怎么学会玩一个游戏」拆成三件事，并用一套与具体游戏无关的工程实现：

1. **看**：把屏幕变成结构化、可行动的世界状态；
2. **玩**：基于状态执行技能、战术和场景流程；
3. **学**：记录结果、归因、形成可验证的记忆，并让下一次表现变好。

**看和玩是两个能力；学是连接它们、让它们持续变好的反馈回路。**
外部攻略是「学」的可选知识来源，不是第三条腿——没有网络也必须能玩。

## 2. 总体架构

```text
┌──────────────────────────── 看（感知层，多速率） ────────────────────────────┐
│ 高帧率（≥50Hz）：抓帧 → 玩家追踪 → 实体/弹幕轨迹 → 镜头位移 → 关卡坐标        │
│ 低帧率（3–5Hz）：OCR → 场景分类 → HP/HUD → 交互提示图标 → 地标/地图          │
│ 可选：L2 状态源（内存/API/模组）——只读、默认关闭、反作弊禁用                  │
│ 输出：WorldState（带 confidence / timestamp / stale 标记）                   │
└───────────────────────────────────┬──────────────────────────────────────────┘
                                    ▼
┌──────────────────────────── 玩（决策/执行层） ──────────────────────────────┐
│ 技能层（本地 ≥50Hz）：face / shoot_at / evade / jump_over / retreat / parry  │
│ 仲裁器：Recover > Evade > Engage > Advance > Explore                          │
│ 战术层（1–5Hz）：选目标 / 推进 vs 清场 vs 后撤 / 资源使用                     │
│ 场景状态机：menu / gameplay / death / equip / cutscene / unknown             │
│ 执行：键鼠/手柄注入 + 逐拍前台校验 + 安全闸 + 审计                            │
└───────────────────────────────────┬──────────────────────────────────────────┘
                                    ▼
┌──────────────────────────── 学（记忆/改进回路） ────────────────────────────┐
│ EpisodeRecorder：环形缓冲（帧缩略图 + WorldState + 输入 + 事件）              │
│ 归因：HP 下降/死亡/险情 → 最近轨迹 → 接触/弹幕/坠落/未知                     │
│ DangerCard：位置 + 触发条件 + 事件证据 + 应对 + 统计 + 置信度 + 状态          │
│ 结果回写：经过危险区是否受伤 → avoided / damage_events → 升降级               │
│ GuideCard（可选）：本地导入攻略事实，带 URL/日期/置信度，默认不联网            │
│ 评测：有卡 vs 无卡、参数 A/B、受击/死亡/推进/通关率                           │
└─────────────────────────────────────────────────────────────────────────────┘
```

原则：

1. **视觉是保底地板**：没有模板、没有内存、没有网络，也能观察和做基础动作；
2. **L2/攻略是可选加速器**：不是通用地基，失败自动降级；
3. **快环不等待慢环**：OCR/场景写缓存，高帧率只读带时间戳的最新值；
4. **模型不进快环**：模型做战略、复盘、调参；事件驱动，约每局数次调用（单次工具调用 3–5 s，不存在 2Hz 的模型环）；
5. **不确定就停/退**：感知置信度低时禁止盲目前进；
6. **所有改动可验证、可回滚**：没有对照数据的“学习”不算学习。

## 3. 看：把画面变成可行动状态

### 3.1 WorldState 目标字段

```json
{
  "schema": 1,
  "t": 1793355000.0,
  "scene": "gameplay",
  "confidence": 0.9,
  "player": {"x": 0.4, "y": 0.8, "vx": 0, "vy": 0, "facing": "right",
              "grounded": true, "hp": 3, "max_hp": 3, "invincible": false, "confidence": 0.8},
  "entities": [
    {"id": 12, "kind": "enemy", "sprite": "mushroom", "x": 0.55, "y": 0.82,
     "vx": -0.02, "vy": 0, "threat": 0.8, "relation": "ahead", "confidence": 0.7},
    {"id": 18, "kind": "projectile", "x": 0.5, "y": 0.3, "vx": -0.2, "vy": 0.1, "time_to_hit": 0.35}
  ],
  "world": {"scroll_s": 2.4, "segment": 2, "ground_y": 0.82, "platforms": [], "hazards": []},
  "ui": {"prompt": null, "icon_prompt": {"key": "Z", "x": 0.5, "y": 0.38},
          "hp_text": "HP.3", "menu": null},
  "game": {"profile": "cuphead", "providers": ["vision"], "stale": false}
}
```

要求：

- 实体带**稳定 ID**（跨帧跟踪），不是每帧匿名点；
- 玩家有位置/朝向/落地/HP/无敌帧，策略才能做方向性决策；
- 位置用**屏幕归一化坐标 + 关卡坐标 `scroll_s`** 双表示；
- 所有字段带 confidence；未知就是 null，不猜。

### 3.2 感知分层

| 层 | 频率 | 内容 |
|:--|:--|:--|
| 快层 | ≥50Hz | 抓帧、玩家模板/颜色追踪、运动簇→轨迹、镜头位移/关卡坐标 |
| 慢层 | 3–5Hz | OCR、场景分类、HP/HUD、交互提示图标、地标/地图 |
| 可选 L2 | 事件驱动 | 只读内存/API/模组，提供精确玩家/敌人坐标；仅本地、默认关闭 |

### 3.3 关键感知能力

- **玩家**：模板 + 颜色校验（拒绝草地/天空误匹配），连续性搜索 + 大跳变共识；
- **实体跟踪**：最近邻关联、平滑速度、相对方位、接近速度；区分己方子弹与威胁；
- **静态危险物**（当前缺口）：地面毒蘑菇/地刺不一定移动，纯帧差会漏；需要颜色/模板/边缘分割或“危险区域”记忆；
- **交互提示**：OCR 文本 + 按键图标模板（黑底 Z 等）双通道；
- **场景**：OCR 关键词 + HP + 近黑屏 + 滞回，避免 gameplay 被误判 dialogue；
- **关卡坐标**：镜头相位相关累积 `scroll_s`，地标签名纠偏；重试归零。纯积分会漂移，
  必须有漂移预算（见 §10 实验 2），未达标前 DangerCard 的位置结论都不可信；
- **坐标模型可扩展**：`place` 是由 profile 声明的坐标元组——横版卷轴用 `scroll_s`，
  固定屏幕（Boss 战）用「阶段 + 阶段内时间」，竖向段落再加 `scroll_y`。当前只实现横版，
  这是已知边界，不是通用结论；
- **受伤检测走快环**：HP 区域像素签名每拍比对（变化才交给 OCR 确认）或受击闪烁检测；
  慢环 OCR 只做确认，不做第一信号；
- **地图/地标**：商店、桥、入口、signpost 模板；入口 = 交互提示出现的位置。

### 3.4 对象级理解（从「看到运动」到「知道它是什么」）

当前最大的认知缺口：实体只是匿名运动簇（`threat` / `parry`），不是「怪物」。
真正可行动的「理解」需要四层：

1. **对象持久性**
   - 稳定 ID + 外观签名（颜色直方图 / 缩略模板 / 感知哈希）；
   - 轨迹年龄、出现/消失、遮挡后重识别；
   - 同一对象跨帧、跨镜头保持身份。

2. **行为语义（不靠外观标签）**
   - 持续靠近玩家 → `approaching`；
   - 在玩家附近时 HP 下降 → `harmful`；
   - 长期跟随、反复从后方出现 → `chaser`；
   - 小而快、从远处飞来 → `projectile`；
   - 接触后加分/消失 → `pickup`；
   - **语义 = 它对玩家会造成什么影响，而不是它叫什么。**

3. **外观聚类与角色继承**
   - 从轨迹裁剪对象缩略图，按外观聚类成原型；
   - 同一簇共享统计：出现次数、导致掉血次数、被击杀次数、是否追击；
   - 新对象先匹配簇，继承角色先验；
   - 人类/攻略/VLM 的命名只用于检索，不直接参与 60Hz 决策。

4. **因果与反事实**
   - 记录「对象出现 → 玩家动作 → HP/位置变化」；
   - 同一类对象重复出现时比较打/躲/忽略的结果；
   - 有效应对绑定到**对象簇**，而不只是坐标；
   - 这与 DangerCard 的 `response_efficacy` 共用验证闭环。

**当前状态（诚实）**：尚未实现对象级理解。没有敌人模板/类别，只有运动轨迹；
Cuphead profile 目前 `face_back=false`（因为左边是墙），也没有 `turn_and_shoot` 技能，
所以「背后有追击者时回头打」目前做不到。这是 P1 的核心缺口。

**验收**（行为级，不是描述级）：

- 怪物靠近前能预测其会造成伤害；
- 背后出现追击者时能停下、转身、持续射击、再恢复推进；
- 「毒蘑菇要跳」能泛化到新位置的同类；
- 有对象记忆组比无记忆组受击/推进显著更好。

## 4. 玩：技能、战术、场景流程

### 4.1 技能层（本地高帧率）

```text
face(direction)            # 转身
turn_and_shoot(direction)  # 停步/锁定朝向，持续射击后再恢复推进
shoot_at(target|direction) # 朝目标/方向射击
evade(threat_id)           # 按预计命中方向跳/冲刺/侧移
jump_over(entity|pit)      # 越过敌人/坑
retreat(duration)          # 后撤拉开
keep_distance(target, r)   # 保持距离
parry(target)              # 粉球格挡
hold_position()            # 停火/等待
```

要求：技能基于预测和状态，不允许“固定间隔盲跳”这种伪技能。

### 4.2 仲裁器

优先级：`Recover > Evade > Engage > Advance > Explore`

- 承诺期内不被低优先级打断；
- 每个技能声明前置条件、承诺时长、可否打断、冷却；
- 战术层只调参数/姿态，不直接抢快环。

### 4.3 场景状态机

```text
menu → gameplay → (death → retry) | (equip → back) | (cutscene → skip) | (pause → resume)
unknown → 松手 + 上报，不按确认
```

- profile 的 `scenes` 声明识别规则、允许按键、恢复脚本与超时；
- 恢复阶梯：白名单按键 → 返回/暂停 → 进程重启（需用户授权）→ 上报；
- 任何新能力都不得绕过安全闸。

### 4.4 安全与执行

- 每拍安全闸：反作弊进程、F12 takeover；
- 每拍前台校验：失焦释放按键 → 尝试重新聚焦 → 失败则暂停；
- 审计日志：所有输入/状态/策略切换可回放。

## 5. 学：让下一次真的变好

### 5.1 GameProfile（结构化知识）

每款游戏一份本地 JSON：

- controls：键位/手柄映射（实测确认）；
- hud/ui：HP、提示图标 ROI/模板；
- scene/skills：场景识别、技能参数；
- player/entities：玩家/敌人/图标模板（本地，不进仓库）；
- map/knowledge：地图节点、危险点、Boss 阶段；
- 每条事实带 `source`、`confidence`、`evidence`、版本。

### 5.2 EpisodeRecorder（发生了什么）

- 15 秒环形缓冲：缩略帧 + WorldState + 输入 + 事件；
- 死亡/受伤/停止时落盘；同一场景停留不重复落盘；
- 目录：`meta.json / events.jsonl / frames.jsonl / frames/*.jpg`；
- 用途：回放、归因、评测、复盘；
- **回溯定位 t_hit**：检测到受伤的时刻晚于被打的时刻（OCR 周期最长约 2 s）。卡片坐标与
  归因必须取缓冲里的受击时刻 t_hit（HP 区域首次变化帧 / 受击闪烁起点），不取检测时刻；
- **保留策略**：每关最多保留 N 个 episode，超出按时间淘汰（有卡片引用的除外）。

### 5.3 DangerCard（哪里危险、怎么应对）

```json
{
  "schema": 1,
  "id": "cuphead/forest-follies/danger-xxxx",
  "place": {"scroll_s": 2.4, "segment": 2, "player_x": 0.4, "player_y": 0.8, "landmark": "tree-2"},
  "trigger": {"kind": "enemy", "template": "mushroom", "relation": "ahead"},
  "event": {"type": "damage", "cause": "contact", "hp_before": 3, "hp_after": 2},
  "response": {"skill": "jump_over", "params": {"before_px": 120}, "timing": "within 0.3 screen"},
  "evidence": ["episode-damage-.../frames/0034.jpg"],
  "stats": {"encounters": 3, "damage_events": 2, "avoided": 1,
            "response_tries": 2, "response_failures": 1},
  "hazard_confidence": 0.7,
  "response_efficacy": 0.5,
  "status": "candidate|validated|trusted|stale"
}
```

**两个量必须分开**：「这里危险」和「这个应对有效」是两件事。

- `hazard_confidence`：这个位置确实危险。重复受伤 → 上升；多次经过从未出现威胁 → 下降；
- `response_efficacy`：应对有效。**执行过 response 且未受伤** → `avoided++`，上升；
  **执行过 response 仍受伤** → `response_failures++`，下降。

生命周期：

1. 受伤/死亡（取 t_hit 时刻的坐标与归因）→ 自动建 `candidate`；
2. 同一位置重复受伤 → 只提高 `hazard_confidence`，**不等于 response 有效**；
3. 经过卡片窗口：执行了 response 且窗口结束仍未掉血 → `avoided++`；执行了仍掉血 →
   `response_failures++`；
4. `response_failures` 达阈值 → 按阶梯换技能（jump → dash → retreat → hold），统计清零重来；
5. `validated` = `hazard_confidence` 达标 **且** `response_efficacy` 达标；`trusted` 还需通过 A/B（§5.5）；
6. 游戏版本变化/长期未验证 → `stale`。

> 现状（2026-10-30）：代码里「同坐标 `damage_events ≥ 2` → `validated`」把两个量混在一起，
> 且 `avoided` 从未被递增。按本节拆分是 P0 第 3 项。

### 5.4 一次学习 vs 统计验证

- **单机、已知坐标的重复危险**：允许 `candidate` 在对应窗口执行一次规避（`danger_reflex`），实现“第一次掉血、第二次就跳”；
- **不确定/泛化场景**：必须统计验证后才 trusted；
- 两者都保留 `evidence` 和开关，可回滚。

### 5.5 结果回写（当前重点）

一次学习不能只看“记了”，要看“有没有用”：

- 经过卡片窗口后是否掉血 → 写回 `avoided` 或 `damage_events`；
- 卡片的 response 在 N 次经过中的成功率；
- 无卡/有卡 A/B：同关卡多次，比较该区域受击率、推进距离、通关率；
- 只有数据支持才升级/保留；否则降级或删除。

### 5.6 可选外部知识（攻略）

- `GuideStore`：本地导入事实卡（title/facts/source_url/fetched_at/confidence/unverified）；
- 引擎不联网；联网/搜索由模型或用户完成；
- 攻略事实必须进游戏验证后才 trusted；
- 无网络时功能完全可用。

### 5.7 地图/物体级泛化

- 坐标背板：先解决“同一位置”；
- 物体背板：从受伤/危险帧自动裁剪候选模板，聚类成“毒蘑菇/地刺/弹幕”类，检测同类就触发对应技能；
- 攻略事实可提示“这类东西要跳”，但必须视觉验证。

### 5.8 模型复盘（game_review）

本地规则（contact → jump_over，projectile → evade）太粗，换技能/调参数正是模型能补位的地方：

- 死亡或 `response_failures` 达阈值时，`game_review` 返回死前 3–6 张关键帧 + 事件时间线 +
  相关卡片统计 + 当前参数；
- 模型提出补丁（换 response、调 timing/params、调 profile 阈值）→ 写入候选 profile；
- 候选经 A/B 评测 N 局优于原版才保存，否则丢弃；每次改动保留 diff 与指标，可回滚；
- 模型调用是事件驱动的，约每局数次，不进快环。

## 6. 数据流：一次受伤的完整路径

```text
高帧率：玩家位置/轨迹/镜头坐标 + HP 区域像素签名 ──► 疑似受击（t_hit）
        │
低帧率：OCR 两次读数确认 HP 3→2（死亡画面则直接确认致命一击）
        │                       │
        │                       ▼
        │             EpisodeRecorder 保存 damage/death episode
        │                       │
        └────────► 回溯到 t_hit：当时的坐标 + 最近轨迹 → contact/projectile/unknown
                                │
                                ▼
                 DangerCard candidate（位置 + 证据 + 默认 response）
                                │
                                ▼
                 下一局经过坐标窗口 → danger_reflex 执行一次
                                │
                                ▼
      经过后是否掉血 → hazard_confidence / response_efficacy 分别回写 → 升降级或换技能
                                │
                                ▼
                 通过 A/B 评测的卡片/参数写入 profile，长期复用
```

## 7. 公开仓库与本地边界

公开仓库只放：

- WorldState / Profile / DangerCard / GuideCard 的 **schema 与接口**；
- 安全说明、反作弊边界、安装/发布文档；
- 不含游戏精灵模板、录像、具体 offset、本机路径、破解相关文件。

本地（不入库）：

- 游戏模板、episode、DangerCard 账本、GuideCard；
- 真值适配器/模组；
- 攻略原文（只存摘要 + URL）。

反作弊游戏：只读也不接，直接拒绝。

## 8. 当前实现状态（2026-10-30）

**已实现**

- WorldState（场景 / HP / 玩家位置 / 实体 / 提示图标 / 快环受击 t_hit / 关卡坐标）；实体轨迹（最近邻关联、速度、相对方位）、己方子弹过滤；
- PolicyRunner：闪避 / 交战停步（累计超时抑制）/ 卡住脱困 / 逐拍前台校验 / 场景门控与恢复脚本 / 异步 OCR 场景监视 / 分阶段耗时；
- EpisodeRecorder（异步录制线程）、KnowledgeStore（DangerCard）、LevelLocator、GuideStore、evaluate/review CLI；
- HP 下降自动建卡（**两次读数确认**）；死亡补卡；`damage_scrolls` 记录每次 t_hit 坐标并取中位数；重复受伤只升 `hazard_confidence`；
- 结果回写：`avoided` / `response_failures` / `response_efficacy`；失败阶梯 `jump_over → evade → retreat → hold`；验证失效自动降级；
- 坐标一致性实测：修复卡片链式合并后 `cards=2 mean=0.089 max=0.100 ≤ 0.2`；
- A/B 对照跑批已开始（单对 60s：有卡组推进 -2.3 屏、执行 validated 卡；无卡组 -0.09 屏），但样本不足以下结论；
- 测试：引擎 **192**、插件 44；实机自动重试 / 记忆检索 / 结果回写 / 换技能均已验证。

**部分实现（有明确局限）**

- 感知仍以运动簇为主，**没有对象级理解**（无敌人模板/类别/chaser 语义）；
- 受伤确认仍依赖慢环 OCR（快环只给 t_hit 信号）；归因取检测时刻最近轨迹，阈值粗；
- 危险反射只执行 `jump_over` / `evade` 的按键，`timing` 未完全使用；
- 帧率：分阶段实测约 **39–44Hz**（波动；带 OCR + 录制），尚需稳定 ≥40；
- A/B 只有单对样本，统计证据不足。

**未实现**

- 对象级理解（ID + 外观签名 + 行为角色 + 外观聚类）与 `chaser`/`turn_and_shoot`；
- 静态危险物视觉检测；
- 技能库 / 仲裁器、战术姿态；
- `game_review` 工具化与补丁 A/B 闭环（目前只有离线 review 包）；
- 地图入口导航 / 路线记忆；
- Forest Follies 尚未通关。

## 9. 路线图与验收

### P0（记忆记得准 + 可测）

1. **受伤信号准确**：快环 t_hit 信号 + OCR 两次读数确认（已完成）；
2. **坐标一致性达标**：卡片链式合并修复后实测 max 0.100（已完成）；
3. **结果回写**：hazard / response 双量、avoided / response_failures、换技能阶梯（已完成）；
4. **评测脚本 + 基线**：evaluate/review CLI、episode/card 指标（已完成）；
5. **帧率稳定 ≥40 Hz**：分阶段计时已接入，实测约 39–44Hz（需稳定）；
6. **A/B 统计**：交替 knowledge on/off 跑 N 局，输出受击/死亡/推进/通关率（进行中）。

**验收**：同一危险点第二次经过的掉血率相对第一次显著下降（10 次经过统计）；自动重试 20 次零人工；
受击/死亡都有 episode 和卡片；坐标漂移有实测值且在预算内；有卡组 A/B 显著优于无卡组。

### P1（会躲会打 + 会理解）

1. **对象级理解**：稳定 ID + 外观签名 + 行为角色（approaching/harmful/chaser/projectile/pickup）+ 外观聚类；
2. **chaser 优先 + turn_and_shoot**：背后追击者时停步、转身、持续射击、恢复推进（不能只是「默认向右」）；
3. 静态危险物视觉检测（处理坐标记忆覆盖不了的情况）；
4. 技能库 + 仲裁器；危险反射按 `response.skill` / `params` 执行；
5. 战术姿态（推进/清场/后撤/保守）；
6. 地图入口导航（walk-until-affordance）。

**验收**：Forest Follies 10 局，受击/分钟相对基线 −50%，到中段成功率 ≥60%；
背后追击者能被识别并处理；同类危险物能泛化到新位置。

### P2（会学 + 泛化）

1. `game_review` 模型复盘 + 候选补丁 A/B；
2. 参数 preset 与自动调参；
3. 攻略导入（可选）；
4. 副本游戏评测矩阵；坐标模型扩展（固定屏幕 / 竖向）；
5. 通关稳定性。

**验收**：Forest Follies 从大地图出发 10 局 ≥7 局通关；有卡组与无卡组各 10 局，有卡组受击/分钟
与通关率显著更好；2–3 款副本游戏可观察/可过菜单/可基础游玩。

## 10. 关键实验（用数据说话）

1. **毒蘑菇一次学习**：记录首次受击坐标 → 生成卡 → 下次经过执行 jump → 比较该点掉血率（开/关 reflex）。
2. **坐标一致性**：两次运行中同一危险点的 `scroll_s` 偏差；超过窗口则修 locator。
3. **有卡 vs 无卡**：同关卡 N 局，比较受击/死亡/推进/通关。
4. **归因准确率**：人工标注少量受击帧，校验 contact/projectile/pit 分类。
5. **帧率预算**：抓帧/玩家/跟踪/OCR 分项 p50/p90。
6. **受伤时延**：t_hit 到检测确认的延迟分布（快环信号 vs OCR）；回溯后卡片坐标与真值的偏差。

## 11. 设计原则（必须遵守）

1. **不以“记录了”为成功，以“下次表现变好”为成功**；
2. **证据优先**：没有 episode/轨迹证据的规律不写成 trusted；
3. **一次学习只用于单机、可回滚、可关闭**；
4. **不确定就停/退/探测**，不盲目前进；
5. **安全闸与状态来源无关**，任何新能力不得绕过；
6. **公开仓库不泄露本地数据**；
7. **先证明 2D 固定视角，再谈 3D**；3D 是另一个量级的项目；
8. **语义来自行为与结果**：先有持久对象，再用「它对玩家做了什么」定义角色，最后才用人类/攻略/VLM 命名；
9. **理解要可行动、可证伪**：不能只是描述画面，必须能预测伤害/选择应对并通过 A/B 验证。

## 12. 最终目标

一句「帮我打 Forest Follies」，插件能：

1. 从大地图找到入口并进入；
2. 在关卡里观察、躲避、战斗、死亡后自动重试；
3. 把每次失败变成带坐标/归因/证据的记忆；
4. 下次经过同一危险点时表现更好；
5. 用数据证明「有记忆」比「没记忆」更强；
6. 引擎不出现任何游戏专用代码，用 1–2 款副本游戏证明通用性。

**验收标准：Cuphead 的 Forest Follies（跑酷关）从大地图出发 10 局 ≥7 局通关，并且有可复现的
「有卡 vs 无卡」对比证据。**
