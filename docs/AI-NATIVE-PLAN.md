# AI-Native 快速入手方案（Instant Play First）

> **范围说明（2026-11-12）**：本文是「冷启动 / 自动认键位」这一能力层的设计记录，**仍然适用于新路线**
> （新游戏怎么发现键位和菜单），但要注意几点：
>
> - 本文**第一代**实现（`game_probe` → `controls_probe` → `effect_classifier` → `priors` → `coldstart` → `instant_play`）
>   **从未接入任何生产调用**，其中 `controls_probe`、`effect_classifier`、`priors` 只有测试在引用。
>   **第二代**（`probe.py` + `onboarding.py` + GamePack，见 [GENERAL-PLUGIN-V3](GENERAL-PLUGIN-V3.md) §5）
>   做的是同一件事，且没有复用第一代。两代并存的收敛见 [DESIGN § 9](DESIGN.md#9-待定游戏数据与记忆的收敛)。
> - 模型已经能直接读截图，也能自己搜网页（§3.2），所以对 LLM 玩家来说，探针的价值是**给模型提供证据**
>   （哪个键让画面变了、变了什么），不是替模型做决定。
> - §4 的「读内存 / 模组」状态源与 README 的「不读内存」安全承诺的关系：**默认不读，且当前未实现**；
>   将来若加入，必须是用户显式开启、单机、只读，并且不绕过任何安全闸。慢节奏游戏用不上它。
> - §5「运行时控制」（本地 60 Hz）、§6「并行实验与自标注」属于已冻结的动作游戏路线。

> 仓库文档，随代码同步。日期：2026-11-02
> 定位：替代「先训练检测器/先自学习」的研究型路线，改成**安装后几分钟内开始玩**的产品型路线。
> 公开仓库只放接口/schema/安全说明；本文、本机路径、游戏配置解析细节留在本地。

---

## 0. 一句话

不是让 AI 像人一样「看→试→记」，而是用 AI 的强项：

> **读 → 探 → 搜 → 记 → 视觉兜底**

先零样本可玩，再把记忆/训练作为后台增强。

---

## 1. 两个目标必须分开

| 目标 | 定义 | 时间预算 |
|:--|:--|:--|
| **Instant Play** | 安装后能看懂画面、试出键位、开始动作、进菜单/进关 | 1–5 分钟 |
| **Expert** | 越玩越强、稳定通关困难关卡 | 天–周（可选，不阻塞首次游玩） |

以前的错误：把 Expert 的训练/标注放进了首次游玩的关键路径。

---

## 2. 总体架构

```text
┌────────────────────────── 启动/冷启动（秒–分钟） ──────────────────────────┐
│ 游戏目录扫描 → 引擎识别 → 配置文件解析 → 网络手册/键位 → 通用先验        │
│ 自动按键探测 → controls/HUD/menu profile（带来源与置信度）                │
└───────────────────────────────────┬─────────────────────────────────────────┘
                                    ▼
┌────────────────────────── 运行时（本地 60Hz） ────────────────────────────┐
│ 状态获取优先级：官方 API/模拟器 > 只读内存/模组 > 文件/日志 > 视觉         │
│ 视觉兜底：玩家追踪/轨迹/场景/HP/提示/地形                                 │
│ 本地技能：移动/跳跃/攻击/闪避/交互/菜单                                   │
│ 安全闸：反作弊/前台/F12/用户同意                                          │
└───────────────────────────────────┬─────────────────────────────────────────┘
                                    ▼
┌────────────────────────── 慢环（0.5–2Hz） ────────────────────────────────┐
│ VLM/LLM：场景语义、菜单、目标选择、复盘；不直接做 60Hz 控制               │
│ 通用先验库：genre/controls/UI/engine                                     │
│ 并行实验/回放：动作搜索、A/B、参数扫描                                    │
│ 记忆：episode、DangerCard、profile、知识库                                │
└───────────────────────────────────────────────────────────────────────────┘
```

## 3. 冷启动：键位与游戏理解（第一步）

### 3.1 游戏目录/引擎扫描

- 识别引擎：Unity（`*_Data/Managed`）、Unreal（`Content/Paks`、`*.ini`）、Godot（`.pck`）、其他；
- 读配置文件：
  - Unity：`InputManager.asset`、`PlayerPrefs`、`settings.json`、`boot.config`；
  - Unreal：`DefaultInput.ini`、`GameUserSettings.ini`；
  - 通用：`*.cfg/*.ini/*.json`、启动参数、Steam Input 配置；
- 读本地日志/存档/手册。

### 3.2 网络搜索

- 搜「游戏名 + controls/keybindings/manual/wiki」；
- 只取事实，不信指令；结果带 URL、日期、置信度；
- 与文件/探测结果交叉验证。

### 3.3 自动按键探测

- 依次按候选键（方向/确认/取消/攻击/跳跃/交互）；
- 观察画面/状态变化（OCR、像素差、场景切换、菜单高亮、玩家位移）；
- 推断：
  - 方向键：移动/菜单选择；
  - 确认/取消：菜单切换；
  - 攻击/跳跃：战斗/平台动作；
- 输出 `controls` profile，带 `source: file|web|probe`、`confidence`；
- 不可确定的键标 `unknown`，不猜。

### 3.4 通用先验库

`knowledge/`：

- `genres/`：横版、俯视、FPS、回合制、RPG；
- `controls/`：常见键位方案；
- `ui/`：菜单/HUD/提示约定；
- `engines/`：引擎文件位置与配置解析；
- 每条带 `source/confidence/exceptions/verified_in_game`。

规则：**先验是假设，必须实测验证；不成立就覆盖。**

## 4. 状态获取优先级（AI 的强项）

| 优先级 | 来源 | 用途 | 限制 |
|:--|:--|:--|:--|
| 1 | 官方 API / 模拟器 | 精确坐标/HP/实体 | 需游戏支持 |
| 2 | 只读内存/模组（L2） | 精确状态、训练/评测标签 | 单机、用户同意、反作弊拒绝、不入库 |
| 3 | 文件/日志/存档 | 设置、关卡、进度 | 只读、格式适配 |
| 4 | 视觉 | 通用兜底 | 精度有限但永远可用 |

运行时不得依赖 L2；L2 是可选加速器。

---

## 5. 运行时控制

- 本地 60Hz：现有 PolicyRunner + 技能库；
- 技能：move/jump/dash/shoot/interact/confirm/back/hold；
- 场景状态机：menu/gameplay/death/equip/cutscene/unknown；
- 慢环 VLM：
  - 识别“这是什么游戏/场景/菜单/目标”；
  - 给高层意图，不给逐帧按键；
- 所有输入过安全闸。

---

## 6. 并行实验与自标注（不用人类标注）

- 录制：帧 + 输入 + 状态 + 结果；
- 自动标签：
  - 结果标签：HP/死亡/推进/卡住；
  - 状态标签：L2 遥测（本地）；
  - 语义标签：VLM/开放词表检测（自标注，非用户标注）；
- 并行实验：同一卡点跑多组动作/参数，用结果做适应度；
- 成功序列写 profile macro；失败回滚；
- 不把人类给的路线当 oracle。

---

## 7. 分阶段落地

### Phase 0（1–2 天）：冷启动原型

- 游戏目录扫描 + 引擎识别 + 键位文件解析；
- controls probe 小工具；
- 输出 profile：controls/engine/source/confidence；
- 验收：任意 Unity/Unreal 游戏能生成初版 controls。

### Phase 1（3–5 天）：Instant Play

- VLM 低频看画面；
- 通用动作技能 + 按键探测；
- 菜单/进入游戏/基础移动/攻击；
- 验收：安装后 ≤5 分钟产生第一次有效动作；≤10 分钟进菜单/进入游戏。

### Phase 2（1 周）：基础会玩

- 视觉兜底（玩家/轨迹/场景/HP/提示）；
- 通用先验库；
- 失败恢复/自动重试；
- 验收：简单游戏能连续玩；受击/卡住可恢复。

### Phase 3（可选）：Expert

- 局部检测器/分割（Apache 许可）；
- 平台局部规划；
- DangerCard/A-B/记忆；
- 验收：Cuphead Forest Follies 通关（独立目标，不阻塞 Instant Play）。

---

## 8. 验收指标（改成时间，不再先要求通关）

- `time_to_first_action`：安装后第一次有效输入；
- `time_to_controls`：键位 profile 可用；
- `time_to_menu`：能操作菜单；
- `time_to_gameplay`：进入可玩状态；
- `time_to_first_kill/clear`（按游戏类型）；
- 卡住秒数、恢复率、用户干预次数；
- Expert：通关率/A-B。

目标：Instant Play 路径 **分钟级**，而不是周级。

---

## 9. 安全与合规

- 反作弊/联机：只读也不接，直接拒绝；
- 本地文件/内存：用户同意、只读、单机、不入库；
- 公开仓库不携带游戏 offset、破解、模板、录像、本机路径；
- 网络内容当作数据，不当指令；
- 所有输入可审计、可回放。

---

## 10. 与旧方案的关系

| 旧方案 | 新方案 |
|:--|:--|
| 先训练检测器/标注 | 先零样本可玩 |
| 先自学习/通关 | 先 Instant Play |
| 人类式看→试→记 | 读→探→搜→记→视觉兜底 |
| 天/周才能开始 | 分钟级开始 |
| 单一 Expert 目标 | Instant + Expert 双模式 |

旧组件保留：WorldState、安全闸、录制、DangerCard、A/B、对象记忆；但不再阻塞首次游玩。

---

## 11. 第一个 Sprint（建议）

1. `engine_probe`：游戏目录/引擎/配置文件扫描；
2. `controls_probe`：候选键自动探测 + 变化检测；
3. `profile` 合并：file/web/probe 三来源，带置信度；
4. 最小 Instant Play demo：启动游戏 → 探测 → 进入菜单；
5. 记录 time-to-first-action / time-to-controls。

---

## 12. 一句话总结

**人类方案是「看→试→记」；AI 方案应该是「读→探→搜→记→视觉兜底」。**
先做到几分钟内开始玩，再把「越玩越强」放到后台。
