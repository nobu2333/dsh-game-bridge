# 玩法协议（PLAY）

> **草稿**（2026-11-12）：这是 M5 要验证的协议，不是已验证的结论。标「待实测」的地方，做 M5 时要用真实数据替换。
> 范围、能力层和代码去向见 [STATUS](STATUS.md)；工具参数与键名见 [CONTROLS](CONTROLS.md)。

## 1. 要回答的问题

模型只通过插件工具，能不能把一款慢节奏游戏玩得比**随机操作**更好？

这份文档定义：模型怎么玩、怎么记录、怎么和对照组比。它不涉及任何本地策略或学习层；
**决策完全由模型做**，插件只负责看清楚、按得准、守住安全边界。

## 2. 适用的游戏

模型一次决策实测约 9 秒（2026-11-02 在 Intent 通道上的测量），所以只考虑**不随时间惩罚玩家**的游戏：

| 类型 | 例子 | 输入 | 状态 |
|:--|:--|:--|:--|
| 方向键益智 | 2048 | 方向键 | **M5 首选**，不需要鼠标 |
| 点击类益智 | 扫雷、纸牌、数独 | 鼠标点击 | 需要先补点击前置缺口（STATUS「下一步」第 3 项） |
| 菜单 / 文字为主 | 视觉小说、回合制 RPG | 键盘 | 未验证 |

不考虑：带实时倒计时的、需要反应速度的。

## 3. 一局的流程

```text
game_selftest            确认引擎就绪、后端是 keyboard（不是 dry-run）
game_windows             找到游戏窗口
game_attach {window}     绑定窗口（需要 DSH 审批）
循环：
  game_snapshot          看棋盘 / 界面
  （模型决定一个动作）
  game_act {button}      执行一个动作
  （确认画面已停止变化，见 §5）
game_stop                松手、解绑
```

**一次一个动作**。不用 `game_plan` 做决策（它是有时长上限的盲循环，只适合「按住方向走一会儿」这类单一动作）。

## 4. 读状态

- **以截图为准**。截图是整个窗口，宽度最大 1280，模型直接看图（2026-11-12 确认 DSH 里的模型可以直接读图片）。
- OCR 只是辅助：`game_snapshot` 的文本里最多带 **12 行**文字和置信度，**没有位置**。
  2048 的分数、`GAME OVER` 这类字可以直接读；棋盘上的数字要靠看图，是否可靠**待实测**。
- 判断「游戏结束」：看画面上的结束提示，同时要有终止规则（§7），不能无限循环。

## 5. 动作和节奏

- `game_act` 默认按住 80 ms，可用 `duration_ms` 调（1–2000）。
- 动画没结束就截图，读到的是过渡帧。可以先调 `game_events`：返回 `static` 再截图。
  `game_events` 比较的是**它自己的上一次调用**，第一次调用只会返回 `baseline`。动画时长**待实测**。
- 每一步先 `game_snapshot` 再 `game_act`，不预先排好一串动作。

## 6. 出错和恢复

| 现象 | 含义 | 做法 |
|:--|:--|:--|
| `source: synthetic fallback` | 引擎没就绪，这是**假画面**，不是游戏 | 停止，报告，不要继续操作 |
| `FOREGROUND_MISMATCH` | 游戏窗口不在前台，输入被拒绝 | 提示用户把游戏切到前台，再继续 |
| 文本里有 `⚠`（遮挡 / 不在前台） | 截图可能是遮挡物 | 同上；或用 `DSH_GAME_BRIDGE_CAPTURE=window` |
| 动作后画面没变 | 动作无效（比如 2048 里该方向已无法移动） | 换方向；连续无变化要计数（§7） |
| 用户按 F12 | 用户夺回控制，输出被锁 | 立即停止，不要重新 attach，除非用户要求 |

## 7. 终止规则

一局在下面任一条件满足时结束，并记录原因：
1. 游戏给出结束画面；
2. 连续 N 步（默认 5）动作后画面都没有变化；
3. 达到步数上限（M5 默认 300 步）；
4. 达到墙钟时间上限（M5 默认 30 分钟）；
5. 用户 F12 或 `game_stop`。

## 8. 记录

每局记录一行，追加到 `experiments/results/` 下的 M5 结果文件。
模型局用 `scripts/record_model_run.py` 从游戏窗口 OCR 读分并写入；对照组用 `scripts/run_baseline.py`，
两边走同一套解析（`engine/dsh_game_core/baseline.py`）。操作步骤见 [M5-RUNBOOK](M5-RUNBOOK.md)。

字段：

| 字段 | 内容 |
|:--|:--|
| `run_id`、`date` | 编号与日期 |
| `player` | `model:<模型名>` / `random` / `fixed-cycle` |
| `game`、`build` | 游戏名与来源（本地开源构建要写出处和提交号） |
| `steps`、`wall_s` | 实际步数与耗时 |
| `score`、`best_tile` | 2048 的最终分数与最大方块（其他游戏换成各自的得分） |
| `end_reason` | §7 的哪一条 |
| `errors` | §6 里出现过的异常次数 |

负结果照样入库。录屏作为证据，但不入库（体积）。

## 9. 对照组与判定

| 对照 | 做法 |
|:--|:--|
| 随机 | 四个方向键等概率随机，走同样的 `game_act` 路径，同样的终止规则 |
| 固定循环 | 例如 `UP, RIGHT, DOWN, LEFT` 轮转（可复用 `scripts/play_pack.py` 的思路） |

- 每组至少 **5 局**，报告分数的中位数和最小 / 最大值，不只报最好一局；
- 对照组命令：`python scripts/run_baseline.py --mode random|cycle --runs 5 ...`（每局开新浏览器 profile，从零开始）；
- 对照组可以用脚本直接调用引擎，因为它不涉及模型；**模型组必须通过真实 DSH 会话和插件工具**；
- **判定 M5 完成**：模型组的**中位数**得分高于两个对照组的中位数，并且最差一局不低于对照组中位数的一半。
  这个阈值是起点，M5 跑完后根据数据修订，不事后放宽。

## 10. 记笔记

M5 阶段**不做**跨局记忆：先看模型在没有记忆时的基线。M5 之后，如果数据显示模型在重复犯同一类错误，
再按 [DESIGN § 9](DESIGN.md#9-待定游戏数据与记忆的收敛) 的方案加每个游戏的笔记。

## 11. 待实测清单

- 模型**读图精度**：已确认能看图，但能否稳定读出 2048 每个格子的数字（尤其是颜色相近的块）仍需实测；
  如果不行，再考虑 OCR 或让插件把棋盘转成文字；
- 每步的真实耗时（截图 + 模型决策 + 动作）；已知：窗口抓屏约 35ms，一次带 OCR 的截图实测 1.6–4.8 秒（2026-11-12）；
- 2048 一次滑动的动画时长，`game_events` 判 `static` 是否可靠；
- 无效动作的比例；
- 窗口级抓屏（`DSH_GAME_BRIDGE_CAPTURE=window`）和默认抓屏在这个游戏上哪个更稳。
